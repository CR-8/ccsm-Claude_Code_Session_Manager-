Claude Code Session Manager

Switch Claude accounts without leaving the session

Keep several Claude subscription accounts signed in at once and change which one a running Claude Code session authenticates as. Same process, same conversation, same context — no /login, no /logout, no restart.

Install Command reference

Sign in once per account. After that A → B → A → C costs no browser. Measured switch latency: ~360 ms. 

  ccsm  claude code session manager        v0.1.0
  ──────────────────────────────────────────────

    PROFILE     IDENTITY            PLAN   AUTH

 ▸ ● Personal    m•••••e@gmail.com   Max    OK
     Company     m•••••y@acme.com    Max    OK
     Friend      Unavailable         —      UNKNOWN

  ↑↓ move  ⏎ switch  a add  q quit

Read this before installing

ccsm stores your Claude OAuth credentials and writes into Claude Code's own config. It depends on undocumented behaviour, reverse-engineered from Claude Code 2.1.259 on Windows.

WindowsVerified
Linux / WSLExpected to work — not validated
macOSNot supported — refuses rather than guessing
Billing attributionUnproven

A switch modifies ~/.claude.json — your project history, trust settings and MCP config live there. ccsm changes only the oauthAccount key and writes a .ccsm-backup first, but that is the blast radius if something is wrong. That switching changes which account Anthropic bills has never been demonstrated end to end.

What it does

Three things that make it safe

One process, one conversation

Claude Code reads its credential while building each request, not at startup. Replace it and the next request goes out as a different account.

PID 27396 → 27396 session cbd3cd03 → cbd3cd03 req #1 ACCOUNT-A req #2 ACCOUNT-B req #3 ACCOUNT-A

An account is two files

The token authenticates; a separate oauthAccount block carries the identity. ccsm publishes both together, or neither.

.credentials.json └ the OAuth token .claude.json → oauthAccount └ accountUuid, email, tier

Fails closed, never silently

A switch verifies the runtime really is the target account, and rolls both files back if it is not. The previous profile stays active.

SWITCH FAILED runtime reports other@x.com, expected me@acme.com → both files restored → personal still active

Installation

Get it running

Requires Python 3.9+ and the Claude Code CLI on your PATH.

git clone https://github.com/REPLACE-ME/ccsm
cd ccsm
.\install.ps1

Installs the ccsm command and the /ccsm skill. If ccsm is not on your PATH afterwards, the installer prints the exact directory to add. 

git clone https://github.com/REPLACE-ME/ccsm
cd ccsm
./install.sh

The architecture should hold on Linux and WSL, but nobody has confirmed the .claude.json location rule there yet. Please open an issue with what you find.

Not supported. Claude Code keeps credentials in the login Keychain, keyed to the config directory, and the naming is undocumented. ccsm refuses rather than guessing — you get a clear message, not a crash.

A Keychain backend is the single most useful contribution right now; the seam is KeychainCredentialStore in ccsm/credentials.py.

Uninstall

./install.sh --uninstall        # Windows:  .\install.ps1 -Uninstall

Removes stored credentials, the command and the skill. Your Claude Code config directory is left alone.

Quick start

From nothing to switching, in four steps

  1. Enrol the account you are already signed in as

    No browser needed — it captures the live credential.

    ccsm adopt personal

  2. Enrol a second account

    This one does need a browser. Open the manager and press a. Use a private window, or claude.ai hands back the account you are already signed in as.

    ccsm

  3. Confirm both are stored

    $ ccsm list
* personal      s*****0@gmail.com       pro      OK        2m ago
  work          w*****k@acme.com        max      OK        1m ago

  4. Switch

    Run it in a second terminal while a session is open — that session changes account on its next request. Or type /ccsm switch work inside the session itself.

    ccsm switch work

Where things live

<ccsm home>/
  profiles.json          profile metadata, no secrets
  store/<id>.json        one account bundle per profile, 0600
  enroll/<id>/           throwaway config dir, used only to run /login
  switch.lock            ccsm's own switch lock

~/.claude/.credentials.json      the OAuth token   — read + atomically replaced
~/.claude.json  → oauthAccount   the identity      — only this key is written
~/.claude.json.ccsm-backup       written once, before the first modification

Mechanism

What a switch actually does

Nine steps, in this order, because the order is what makes it safe.

The sequence

  1. Take ccsm's switch lock
  2. Wait out Claude Code's OAuth refresh lock, if held
  3. Read the live credential
  4. Save it back to the profile it belongs to harvest
  5. Read the target profile's stored bundle
  6. Publish credential and oauthAccount atomically
  7. Verify the runtime reports the target accountUuid
  8. Mark the target active
  9. Release the lock

Steps 3–4 are the ones that are easy to skip. Claude Code refreshes OAuth tokens in place, so the live credential drifts ahead of the store. Publish over it without harvesting and the outgoing profile keeps a stale token — sending you back to a browser you did not need.

Anything after step 6 that fails rolls both files back exactly as they were, leaves the previous profile active, and fails closed.

Safety

What it guards, and what it does not

  • Silent account substitution. ANTHROPIC_API_KEY and friends are scrubbed from every child process. Without that, an unauthenticated runtime falls through to whatever key is in your environment and reports itself logged in as a different account.
  • Publishing an unverified identity. A switch confirms the runtime authenticates as the target accountUuid before marking it active, and rolls back if not.
  • Destroying a login you did not enrol. A switch refuses to publish over a credential ccsm holds no copy of.
  • Mis-attributing a credential. Harvest requires a positive identity match; a missing identity is never read as agreement.
  • It is not a vault. Anything that can read ~/.claude/.credentials.json can read ccsm's store. It holds the same class of secret in the same trust domain — just more than one of them.
  • Out of scope, permanently. Automatic rotation, switching in response to a rate limit, or anything that evades usage controls. Switching is an explicit user action by design.
